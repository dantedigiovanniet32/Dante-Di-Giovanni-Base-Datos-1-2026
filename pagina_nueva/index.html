¿Que es SQL?

El lenguaje de consulta estructurada (SQL) es un lenguaje de programacion para almacenar y procesar informacion en una base de datos relacional. Una base de datos relacional almacena informacion en forma de tabla, con filas y columnas que representan diferentes atributos de datos y las diversas relaciones entre los valores de datos. Puede usar las instrucciones SQL para almacenar, actualizar, eliminar, buscar y recuperar informacion de la base de datos. Tambien puede usar SQL para mantener y optimizar el rendimiento de la base de datos.

Historia de SQL

SQL se invento en la decada de 1970 con base en el modelo de datos relacional. Al inicio se conocia como el lenguaje de consultas estructuradas en ingles (SEQUEL). Mas tarde, el termino se abrevio a SQL. Oracle, antes conocido como Relational Software, se convertio en el primer proveedor en ofrecer un sistema comercial de administracion de bases de datos relacionales SQL.

Joins

Lo que hace un join es basicamente unir datos de dos tablas usando una columna en comun que generalmente es la primary key.

Inner join

Devuelve solo las filas que coinciden en ambas tablas.

Left join

Devuelve todas las filas de la tabla izquierda + las que coinciden de la otra tabla.

Right join

Devuelve todas las filas de la tabla derecha + las que coinciden de la otra tabla.

DER (Diagrama Entidad-Relacion)

El modelo entidad relacion (ERD o modelos ER) es una herramienta que permite representar de manera simplificada como personas, objetos o conceptos se relacionan entre si. Se utiliza para exponer como se organiza la informacion en una base de datos.

La creacion del modelo entidad relacion para su aplicacion en el diseno de bases de datos se le atribuye a Peter Chen, profesor del MIT, quien publico en 1976 el documento "Modelo entidad-relacion: hacia una vision unificada de los datos".

El modelo entidad relacion incluye tres elementos basicos:

Entidades

Son las personas, objetos o conceptos de los que trata una base de datos. Por ejemplo, en una base de datos de ventas de un negocio, las entidades podrian ser, entre otras, "Cliente", "Producto", "Factura" o "Direccion".

Atributos

Describen las propiedades que posee cada entidad. En el ejemplo anterior, atributos de la entidad "Cliente" podrian ser "Nombre", "Primer Apellido", "Fecha de nacimiento", etc.

Relaciones

Sirven para crear vinculos entre parejas de entidades. Siguiendo con el ejemplo, cada "Cliente" esta vinculado a una "Direccion", a uno o varios "Productos", etc.

Funciones de Agregacion

COUNT()

Cuenta las filas que coinciden con una condicion. Se puede aplicar sobre todas las filas de una tabla o unicamente sobre los valores de una columna concreta. 

SELECT COUNT(*) FROM Clientes;
SELECT COUNT(Telefono) FROM Clientes;

COUNT(*) cuenta filas, mientras que COUNT(columna) cuenta solo los valores no nulos de esa columna, por lo que ambos resultados pueden diferir.

SUM()

Suma todos los valores numericos de una columna. Se usa principalmente en columnas de tipo entero o decimal, y su resultado es un unico valor total. 

SELECT SUM(Precio_total) FROM Pedidos;

Si la columna contiene valores NULL, esos valores se ignoran en lugar de dar el total a cero. Puede combinarse con GROUP BY para obtener subtotales por cada grupo.

AVG()

Calcula el promedio o media aritmetica de los valores numericos de una columna. Es equivalente a dividir el resultado de SUM() por la cantidad de valores. 

SELECT AVG(Precio_unitario) FROM Detalles_pedidos;

Al igual que SUM(), omite los valores nulos. En motores como MySQL el resultado suele ser un DECIMAL, no un entero, para conservar los decimales.

MIN() y MAX()

Devuelven respectivamente el valor menor y el mayor de una columna. Funcionan tanto con numeros como con texto y fechas, respetando el orden alfabetico o cronologico en esos casos. 

SELECT MIN(Precio_total) FROM Pedidos;
SELECT MAX(Precio_total) FROM Pedidos;

Se incluyen en SELECT sin GROUP BY cuando se quiere un unico valor de toda la tabla, y se convierten en el maximo o minimo de cada grupo cuando se usan con GROUP BY.

GROUP BY

Agrupa las filas que comparten el mismo valor en las columnas indicadas. Se usa para aplicar funciones de agregacion sobre cada grupo por separado en lugar de sobre toda la tabla. 

SELECT id_cliente, COUNT(*) AS total
FROM Pedidos
GROUP BY id_cliente;

Todas las columnas del SELECT deben aparecer en el GROUP BY o estar dentro de una funcion de agregacion, de lo contrario el motor devuelve un error.

HAVING

Filtra los grupos ya formados despues de aplicar la agregacion. Se diferencia de WHERE en que este ultimo filtra filas antes de agrupar, mientras que HAVING filtra el resultado agrupado. 

SELECT id_carnicero, COUNT(*) AS total
FROM Pedidos
GROUP BY id_carnicero
HAVING COUNT(*) > 1;

Permite condiciones sobre el resultado de funciones de agregacion, por ejemplo HAVING SUM(precio) > 10000, algo que WHERE no puede hacer.

Diccionario de Datos

El diccionario de datos es un recurso centralizado que define y describe la estructura, el contenido y el significado de los datos de un sistema o base de datos. Actua como una guia de referencia que documenta metadatos clave sobre conjuntos de datos, como nombres de campos, tipos de datos, valores permitidos y relaciones entre elementos. El objetivo principal de un diccionario de datos es garantizar la coherencia y la claridad en la forma de interpretar, compartir y utilizar los datos en los distintos equipos.

A medida que las organizaciones crecen y adoptan arquitecturas de datos mas complejas, un diccionario de datos se convierte en una herramienta esencial para reducir la confusion, mejorar la comunicacion y respaldar los esfuerzos de calidad de los datos. Juntas, estas herramientas favorecen la coherencia, la transparencia y la colaboracion eficaz entre los equipos de datos y de negocio.

Normalizacion

La normalizacion es la tecnica que sirve para organizar los datos dentro de las tablas de manera eficiente. Su objetivo es reducir la redundancia, es decir, la duplicacion de un mismo dato en varios lugares, y con ello evitar problemas de inconsistencia cuando se inserta, actualiza o elimina un registro.

Aplicarla significa cumplir reglas sucesivas. Cada forma normal exige el cumplimiento de la anterior, por lo que los pasos van de menor a mayor exigencia: primero 1FN, luego 2FN y finalmente 3FN.

Para que una tabla se considere en primera forma normal, debe cumplir los siguientes criterios:

  • Una sola celda no debe contener mas de un valor (atomicidad).
  • Debe haber una clave primaria para identificacion.
  • No debe haber filas ni columnas duplicadas.
  • Cada columna debe tener solamente un valor por fila.

La 1FN solamente elimina los grupos repetitivos, no la redundancia. Por eso existe la 2FN. Una tabla esta en segunda forma normal si cumple los siguientes criterios:

  • Ya esta en 1FN.
  • No tiene dependencia parcial: todos los atributos no claves dependen totalmente de la clave primaria.

Una tabla en 2FN ya elimino los grupos repetitivos y la redundancia, pero todavia puede tener dependencias transitivas. Esto significa que un atributo no principal depende de otro atributo no principal, y eso es justamente lo que elimina la tercera forma normal.

Para que una tabla este en 3FN, debe cumplir:

  • Estar en 2FN.
  • No tener dependencias transitivas entre los atributos que no son clave.
